Corrected assumptions:
- stale assumption:
  - filesystem staging of `IMPORT.CFG` could be made a hard-gated authoritative check by reading sector `0` back directly from the block device at `lba=2083`
- current evidence:
  - that direct readback is not reliable enough to use as a correctness gate for every payload shape
  - during live tests on the same panel and same day:
    - filesystem-staged delete payloads sometimes matched the direct readback probe
    - filesystem-staged upserts often did not match the direct readback probe
    - the later `EXPORT.CFG` verification still reflected the semantic mutation correctly
- updated interpretation:
  - direct `IMPORT.CFG` sector reads are still useful diagnostics for reversing
  - they should not currently be treated as the authoritative pass/fail test for filesystem-staged mutations
  - the authoritative post-apply check remains a fresh `EXPORT.CFG` pull

Write-path findings:
- pure raw block writes of the encoded `IMPORT.CFG` sector can be written and read back, but they were still not sufficient on their own to trigger a real semantic add/edit/delete
- the working write path remains:
  - enter setup mode
  - stage `IMPORT.CFG` through the mounted filesystem path
  - unmount
  - run the older validated accept sequence:
    - `52 01 02`
    - `52 01 24`
    - `52 01 02`
    - `52 01 0C`
    - plus `80 01 14` / `80 01 0F` responses if the panel asks
- the more ambitious packet-driven accept rewrite from the transport review was regressive on the live panel and was removed

Session teardown findings:
- inline write-session teardown still often ended on `sections_states ... 80`
- a second cleanup HID session using the same exit pattern as read cleanup reliably finished the panel exit to `sections_states ... 90`
- current implementation:
  - write sessions now expose `write_cleanup_mode=auto|none|exit-only|login-exit`
  - default `auto` runs a second cleanup session only when the inline exit does not finish on `0x90`

Practical conclusion:
- keep the read-session improvements
- keep the setup-mode helper improvements
- keep filesystem staging as the default stable write path
- keep direct staging as an explicit experimental/debug mode, not the normal operator path
- keep fresh `EXPORT.CFG` verification as the final authority for user CRUD
